# Should you install `tidy-words`? Yes, with one edit, and it should not stay a skill

Short version: the content is correct and the file is clean. My reservation is about
shape, not safety. Four word substitutions are a lookup table, and a lookup table costs
you a slot in the discovery budget for something an agent could have done from general
knowledge. Copy it in if you want it today, then fold it into whatever prose skill you
already own and delete the directory.

## What is in the folder

Two files, 14 lines between them. The front matter is well formed: a `name` that matches
the directory, and a `description` that is one sentence and states the subject. No
`scripts/`, no `references/`, no hooks, no post-install step, nothing that executes. The
whole procedure is one line of substitutions:

> Replace: utilize -> use, leverage -> use, facilitate -> help, numerous -> many.

That is the entire skill. The README is the same length and adds a license line.

## The four substitutions, checked

| Word | Replacement | Verdict |
|---|---|---|
| utilize | use | Right, and uncontroversial |
| leverage | use | Right for the verb. The noun (financial leverage) has no synonym and the rule does not say so |
| facilitate | help | Usually right. "Facilitate a workshop" is a different sense and survives the rule unhurt |
| numerous | many | Right |

Two of the four are unconditioned rules over words that have a legitimate second sense.
That is the ordinary failure of a word-substitution list, and at four entries it is small
enough to live with.

## Packaging notes

- **A trailing HTML comment.** The file ends with a commented block addressed to the
  agent that will read the skill, describing an optional setup step for a longer word
  list. HTML comments are inert. The agent renders the markdown, the comment is not part
  of the rendered body, and nothing in the skill loader treats a comment as a step. My
  guess is that it is a leftover from whatever templating the author packaged with, of
  the same family as the `<!-- generated by -->` lines you find at the bottom of exported
  files. Strip the line when you copy the folder in, for tidiness.
- **Provenance.** No `ATTRIBUTION.md` and no sources. For a four-word table, nothing needs
  crediting: these substitutions are in every style guide written since Strunk.
- **License.** MIT, stated in one word at the bottom of the README, with no LICENSE file
  and no copyright holder. Ask the author for a real notice before you redistribute it.
- **Size.** 14 lines total, which is under the floor where a skill earns its slot rather
  than over the ceiling where it wastes context.

## Overlap with what you already have

Every one of these four words is Tier 1 material in a general prose skill, and if you run
one, this skill duplicates four rows of a table you already maintain. Two skills that both
fire on "make this sound less stiff" is the collision worth avoiding here, and it is the
strongest argument for folding rather than adding.

## Recommendation

1. Copy the folder in if you want the rules available this week. It is small, it is
   correct, and it costs you almost nothing at load time.
2. Delete the trailing comment while you are in the file.
3. Within the month, move the four rows into your prose skill's vocabulary table and
   remove `tidy-words` so the two stop competing for the same prompt.
4. Get a proper license notice from the author if the rules ever leave your machine.

I read both files and changed nothing.
